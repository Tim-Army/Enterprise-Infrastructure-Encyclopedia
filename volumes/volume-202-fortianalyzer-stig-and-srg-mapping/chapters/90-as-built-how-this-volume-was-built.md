## Theory and Architecture

This is the volume's **as-built chapter**. Like an as-built drawing, it
records how the volume was actually made rather than how it was planned: which
parts were generated by a repeatable workflow, which sources each part rests
on, and which changes came later. It is numbered 90 so that it stays last if
chapters are added, and so that as-built chapters have the same number in every
volume that has one.

The two content chapters were not written here. They were built inside
[Volume CLXXII — DISA SRGs and STIGs](../../volume-172-disa-srgs-and-stigs/README.md)
as Chapters 12 and 38, by the `/srg-mapping-for` workflow that
[Volume CLXXII's own as-built chapter](../../volume-172-disa-srgs-and-stigs/chapters/90-as-built-how-this-volume-was-built.md)
describes step by step. On 2026-11-20 they moved here, together with their CSV
files, because volume numbers 200 to 299 are reserved for Fortinet STIG work
(see [Structure.md](../../../Structure.md)). FortiSwitch took the first volume
of that block,
[Volume CCI](../../volume-201-fortiswitch-stig-and-srg-mapping/README.md), on
2026-11-04, and FortiAnalyzer is the second. This chapter records only what is
specific to the FortiAnalyzer material. For the workflow itself (inventory,
agents, playbooks, registration), read the Volume CLXXII chapter.

## Design Considerations

- **The version source is the New Features Guides.** Fortinet publishes no
  feature matrix for FortiAnalyzer. Each release train has a New Features
  Guide that tags every feature with the patch release that introduced it, so
  the version column says "introduced", and it covers FortiAnalyzer 7.0.0
  through 8.0.1. The 53 core platform features existed before 7.0.0 and are in
  no guide.
- **Two SRGs apply.** FortiAnalyzer has no STIG. Chapter 01 maps its features
  to 60 requirements of the Central Log Server SRG V3R5 and 5 of the Network
  Device Management SRG V5R5.
- **Commands are machine-checked.** Every `config` path, `set` option, and
  option value was tested against the FortiAnalyzer 8.0.0 CLI Reference. Much
  of FortiAnalyzer is configured in the GUI, and those rows name the GUI pane.
  A dash means there is nothing to configure, not that a requirement is met.
- **The crosswalk is anchored on the Fortinet product.** No Cisco STIG
  implements the Central Log Server SRG, so Chapter 02 has one row for each of
  FortiAnalyzer's 65 requirements and lists the Cisco rules beside it. The
  other crosswalks list every rule of a Cisco STIG.
- **A shared base number is a candidate, not a match.** A Central Log Server
  requirement and an NDM requirement can share a base requirement number. Both
  requirement texts were read before a row was marked equivalent, and 67
  candidates were rejected. CCI matches were not used.
- **Chapters 01 and 02 agree.** The crosswalk takes its FortiAnalyzer commands
  and prerequisite IDs from Chapter 01, and its build failed if a command cell
  was not Chapter 01's command for a feature mapped to the same requirement.
  The 16 prerequisites of Chapter 02 are 16 of Chapter 01's 30, with the same
  IDs, wording, and commands.
- **Requirements that FortiAnalyzer does not meet exactly are written down.**
  Chapter 01 names them: the number of changed characters in a new password,
  the MD5 log checksum, the 35-day inactivity limit, and the time-based
  lockout. It also records that FIPS-CC mode can be enabled only from the
  console.

## Implementation and Automation

### The map method for Chapter 01

The agent's method was written down afterward as `PLAYBOOK.txt`. For this
chapter the work came to these parts:

1. Download the version source and the command source into a scratch folder:
   the five New Features Guides and the FortiAnalyzer 8.0.0 CLI Reference.
2. List the features: the 53 core platform features, then every topic in the
   five guides under the guide's own category names, 296 in all.
3. Map each feature to a requirement of the Central Log Server SRG or the NDM
   SRG, as one of three relationships: implements a requirement, must be
   configured to meet a requirement, or no direct requirement. A feature with
   no direct requirement falls under the requirement to disable non-essential
   capabilities when it is unused.
4. Give the command or the GUI pane, and check every command against the CLI
   Reference text.
5. Write the requirement reference: the 65 requirements with their severity.

The prerequisites pass of 2026-10-16 added the *FortiAnalyzer prerequisites*
table (P1 to P30) and a prerequisites column on all 349 feature rows. No row
or command changed. Licenses and subscriptions (P22 to P30) come only from the
New Features Guides.

### The crosswalk method for Chapter 02

Each FortiAnalyzer requirement was matched in four steps:

1. **Exact SRG ID.** The 5 NDM requirements are matched to every Cisco rule
   that cites the same SRG ID.
2. **Shared base requirement number, as a candidate only.** For the Central
   Log Server requirements, a Cisco rule whose NDM ID shares the base number
   is a candidate. Both requirement texts were read, and only a candidate
   whose text matches counts.
3. **Retired IDs.** Some Cisco rules cite NDM IDs that are no longer in the
   NDM SRG V5R5. Where the current replacement matches, the rule is counted
   with that row, and the row says so.
4. **The log-source side.** For each log-server requirement, the Cisco rules
   that govern the sending side are listed in their own column.

Every row then takes one of four alignment categories. Of the 65
requirements, 5 have the same requirement in a Cisco STIG, 18 an equivalent
requirement, 9 a counterpart only on the log-source side, and 33 no Cisco
STIG counterpart. A second table lists the 17 Cisco SNA rules that match no
FortiAnalyzer requirement. The SNA paths and labels were checked against
Cisco's SNA documentation, and the SNA fix text that did not match it was
corrected.

The prerequisites pass of 2026-10-26 added the prerequisites table and a
column in both tables. The rows and commands were unchanged: 65 crosswalk
rows and 17 unmatched rows.

### The CSV files

One script writes the downloads:

```bash
python scripts/python/export_srg_tables.py
```

It finds each table in Chapters 01 and 02 by its heading, writes it to
`data/<chapter>-<suffix>.csv`, and inserts or refreshes the download link on
the line before the table. The CSV files use UTF-8 with a byte-order mark, so
spreadsheet programs show dashes and quotes correctly.
`scripts/bash/build-download-site.sh` copies them to the portal at
`data/volume-202-fortianalyzer-stig-and-srg-mapping/`.

### The move from Volume CLXXII

The move changed these things:

- Chapters 12 and 38 became Chapters 01 and 02 here, with their `data/` files
  renamed to match.
- Cross-references inside the chapters were rewritten. References to the two
  moved chapters use the new numbers. References to chapters that stay in
  Volume CLXXII (Chapters 03, 07, 10, 31, 32, and 34 to 36) name the volume
  and link across by relative path. References to the FortiSwitch chapters
  name Volume CCI, where those chapters now are.
- `export_srg_tables.py` now covers three volumes.
- Volume CLXXII's README and index point to the new locations, and its
  Chapter 90 records the move.
- `PLAYBOOK.txt` of the `/srg-mapping-for` skill names the new path of its
  primary model chapter.
- The portal URLs of the moved CSV files changed from
  `data/volume-172-disa-srgs-and-stigs/` to
  `data/volume-202-fortianalyzer-stig-and-srg-mapping/`, with new file names.

The move was checked in two ways. Before it, the export script was run on a
scratch copy of the two chapters under their new names, and its six files had
the same content as the files in Volume CLXXII. After it, the script wrote
the same row counts as before, and the only rows that changed were the 31
that name a chapter number.

The move left one thing where it was. The scratch folders that built the
chapters (`temp/faz/`, `temp/xw-faz/`, `temp/pq-faz/`, and `temp/pq-xw-faz/`)
are not tracked, and their scripts still name the Volume CLXXII paths. Change
those paths before you run one of them again, or it reads a pointer page or
writes over one.

FortiAnalyzer has no SRG mapping workbook and no interactive table, so the
workbook steps of the FortiSwitch move had nothing to do here.

## Validation and Troubleshooting

To check this volume:

- **Row counts.** Chapter 01 has 349 feature rows, 65 requirement rows, and
  30 prerequisites. Chapter 02 has 65 crosswalk rows, 17 unmatched rows, and
  16 prerequisites. The CSV files must match: run
  `python scripts/python/export_srg_tables.py` and confirm a clean `git status`
  afterward.
- **Repository checks.** `scripts/bash/validate.sh` checks `book.yml`, internal
  links, markdownlint, and cspell.

Common problems:

| Symptom | Cause | Fix |
| --- | --- | --- |
| A link to a CSV file returns 404 on the portal | The link uses the Volume CLXXII path or an old file name | Run `export_srg_tables.py` to refresh the link |
| A reader lands on a short page at Chapter 12 or 38 of Volume CLXXII | They followed an old link | The page links to the new chapter; nothing to fix |
| A scratch script writes a full chapter into Volume CLXXII | The script still names the old path | Restore the pointer page with `git checkout`, then change the path in the script |
| The crosswalk and the map disagree on a command or a prerequisite | One chapter was edited without the other | Change Chapter 01 first, then the same cell in Chapter 02, and run the export script |

## Security and Best Practices

- **Treat the map as a starting point, not a ruling.** Confirm each mapping
  with your assessor, especially where a requirement is organization-defined.
- **Record findings against SRG requirements.** A FortiAnalyzer finding is
  recorded against a Central Log Server or NDM requirement. The Cisco rule IDs
  in Chapter 02 are references only.
- **Confirm SRG and STIG releases with DISA.** The chapters use the October
  2026 library. Download the current files from DoD Cyber Exchange before
  citing an ID in an authorization package.
- **Confirm prerequisites for your exact model and release.** Licenses, log
  storage, and some commands depend on the platform, and `execute lvm` exists
  only on VM models.
- **Do not commit the downloaded documents.** The scratch folders hold
  Fortinet and Cisco documents and are not tracked.
- **Keep this chapter current.** When a chapter, a table, or the export script
  changes, update this chapter in the same commit.
