# Volume CLV — Glossary

| Term | Definition |
|:---|:---|
| **CDR** | Cloud Detection and Response — Sysdig Secure's runtime threat detection and response, powered by Falco, with five-second detection: an alert reaches an analyst seconds after the malicious behavior, fast enough to respond before an ephemeral container disappears. |
| **CIEM** | Cloud Infrastructure Entitlement Management — managing who and what can do what in the cloud. Sysdig's distinctive angle is runtime: it observes which permissions are *actually used* and recommends right-sizing entitlements to match, removing permissions granted but never exercised. |
| **CNAPP** | Cloud-Native Application Protection Platform — one platform unifying detection and response, vulnerability management, posture (CSPM), entitlements (CIEM), and compliance. Sysdig's is *runtime-first*: every capability draws on shared deep runtime data. |
| **CSPM** | Cloud Security Posture Management — continuously checking cloud and Kubernetes configurations against best practice and finding misconfigurations. In Sysdig's CNAPP, posture can be prioritized by runtime context: a misconfiguration on a running, exposed workload matters more than one on a dormant resource. |
| **Detection-as-code** | Falco's model: detections written as versioned, reviewable, testable YAML rules — a condition on runtime events plus an output when it matches — so detection knowledge is a shareable artifact mapped to MITRE ATT&CK. |
| **Drift detection** | Detecting that a running container differs from its original image — a new binary or file that was not in the image is a strong sign of tampering or compromise, caught signature-free by comparing runtime behavior to the immutable image. |
| **eBPF** | extended Berkeley Packet Filter — a technology for running safe, sandboxed programs inside the Linux kernel. Sysdig and Falco use it to instrument *system calls*, capturing ground-truth of what actually happened with deep visibility, low overhead, no application changes, and one agent per host. |
| **Falco** | The open-source runtime security engine created by Sysdig and donated to the CNCF — the de-facto standard for Kubernetes/container runtime threat detection. It watches workload behavior via eBPF and alerts in real time on suspicious actions. The engine beneath Sysdig Secure's CDR and the subject of LFS254. |
| **Five-second detection** | Sysdig's stated runtime-detection speed — a malicious behavior surfaces as an alert within about five seconds, fast enough to matter for short-lived containers. |
| **In-use (runtime) vulnerability prioritization** | Prioritizing the vulnerabilities in packages that are *actually loaded and executed at runtime* over the far larger list of CVEs merely present in an image — focusing remediation on the real, reachable risk rather than raw CVE counts. |
| **Kraken Hunter** | Sysdig's signature Credly-badged accreditation — a hands-on workshop of labs and presentations followed by an exam, validating skill using Sysdig tooling for cloud and container security. |
| **LFS254** | "Detecting Cloud Runtime Threats with Falco" — the ~20-hour open-source training course built by the CNCF, the Linux Foundation, and Sysdig; the free, foundational Falco path. |
| **Partner Technical Accreditation** | Sysdig's badge program for partner teams, awarding Credly badges per level through the enablement portal. |
| **Runtime-first security** | Securing what is *actually running* — detecting and responding to threats in production — as the anchor of the security program, complementing agentless posture (what *could* be wrong) with what *is* happening right now, catching zero-days, drift, and insider actions that posture is blind to. |
| **Shared runtime data** | The unifying advantage of Sysdig's CNAPP: one deep runtime observation feeds vulnerability prioritization, posture, entitlements, and detection at once, making each sharper than a standalone tool and powering observability (Sysdig Monitor) from the same foundation. |
| **Sysdig Monitor** | Prometheus-compatible observability (monitoring) for cloud, containers, and Kubernetes, sitting alongside Sysdig Secure on the same deep runtime data — reflecting the convergence of security and observability. |
| **Sysdig Secure** | Sysdig's enterprise runtime-first CNAPP — unifying Falco-powered CDR, vulnerability management, CSPM, CIEM, and compliance on shared eBPF-captured runtime data. |
| **System call (syscall)** | The interface through which a process asks the kernel to do anything (open a file, make a network connection, execute a program). Instrumenting syscalls via eBPF gives ground-truth of what a workload actually did — harder to evade than application logs. |
