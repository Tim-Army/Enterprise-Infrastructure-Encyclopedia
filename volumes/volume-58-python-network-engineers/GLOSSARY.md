# Volume LVIII Glossary

Definitions for terms used in **Volume LVIII — Python for Network Engineers**,
alphabetized. See also the [volume index](INDEX.md) and the
[master glossary](../../GLOSSARY.md) for cross-volume terminology.

**Genie / pyATS** — Cisco's Python test framework: device connections, structured parsers,
and structured `diff` for validation. Used in Chapters 03 and 08.

**GitOps** — Managing infrastructure by keeping intended state in Git and reconciling
devices to it through CI/CD. Used in Chapter 09.

**Jinja2** — The templating engine used to render device configuration from data. Used in
Chapter 06.

**NAPALM** — A multi-vendor abstraction library with normalized getters and merge/replace
config management (diff, commit, rollback). Used in Chapter 04.

**ncclient** — The Python NETCONF client library. Used in Chapter 05.

**Netmiko** — The multi-vendor SSH automation library for network devices. Used in
Chapter 02.

**NETCONF** — A model-driven management protocol over SSH (XML, datastores, commit/
rollback). Used in Chapter 05.

**Nornir** — A pure-Python automation framework providing inventory, parallel execution,
and plugins. Used in Chapter 07.

**ntc-templates** — A community library of TextFSM templates for parsing `show` output.
Used in Chapter 03.

**RESTCONF** — A model-driven management protocol over HTTP (JSON/XML) exposing YANG
models. Used in Chapter 05.

**Source of truth** — The authoritative data model (e.g., NetBox) that drives inventory,
variables, and intended state. Used in Chapter 09.

**TextFSM** — A template-based state-machine parser for turning CLI text into structured
data. Used in Chapter 03.

**TTP (Template Text Parser)** — A reverse-template parser for custom output formats. Used
in Chapter 03.

**YANG** — The data-modeling language defining the structure used by NETCONF/RESTCONF.
Used in Chapter 05.
