# Volume LXXVI Glossary

Definitions for terms introduced in **Volume LXXVI — Okta Certification Tracks**.
See the [master glossary](../../GLOSSARY.md) for cross-volume terms.

- **Access Gateway (OAG)** — Okta's reverse proxy that extends SSO and policy to on-prem, header-based, and legacy web applications that cannot use modern federation.
- **Adaptive MFA** — context-aware multi-factor authentication that steps up requirements based on risk signals (network, device, location, behavior).
- **API Access Management** — Okta acting as an OAuth 2.0 authorization server, issuing scoped access tokens to protect APIs.
- **Auth0** — the Customer Identity Cloud (CIC) platform Okta uses for customer-facing (B2C/B2B) application identity.
- **Authentication policy** — per-application rules with conditions (group, network, device, risk) and actions (allow, deny, require factor).
- **Board defense** — the Technical Architect exam component where the candidate presents and defends a solution design before Okta architects.
- **Customer Identity Cloud (CIC)** — Okta's platform (built on Auth0) for securing customer-facing applications.
- **FIDO2 / WebAuthn** — phishing-resistant authentication factors (passkeys) that defeat credential phishing.
- **Lifecycle Management (LCM)** — automation of the identity lifecycle: provisioning on create, updating on change, and deprovisioning on deactivation.
- **OIDC (OpenID Connect)** — an identity layer on top of OAuth 2.0 that issues ID tokens (JWTs); the modern SSO standard.
- **OIN (Okta Integration Network)** — Okta's catalog of pre-built application integrations.
- **Okta Identity Governance (OIG)** — governance features: access requests, access certifications, and separation-of-duties policies.
- **PKCE** — Proof Key for Code Exchange; the OAuth 2.0 extension that secures the Authorization Code flow for public clients (SPA/mobile).
- **ProctorU** — the online proctoring service (Guardian Browser) that delivers Okta certification exams.
- **SAML 2.0** — an XML-based federation standard for single sign-on between an identity provider and service provider.
- **SCIM** — System for Cross-domain Identity Management; the standard API for provisioning users to downstream applications.
- **Separation of duties (SoD)** — a governance control that prevents one person from holding a conflicting combination of entitlements.
- **SWA (Secure Web Authentication)** — Okta's method of securely storing and replaying credentials for apps without federation support.
- **ThreatInsight** — Okta's feature that blocks or audits requests from IP addresses observed in credential-based attacks.
- **Universal Directory (UD)** — Okta's flexible cloud profile store for users, groups, and attribute mappings across sources and apps.
- **Workflows** — Okta's no-code, event-driven automation engine for identity tasks.
- **Workforce Identity Cloud (WIC)** — Okta's platform for securing employee (workforce) access.
