# Volume CLXIV — Glossary

| Term | Definition |
|:---|:---|
| **App Studio** | Pega's low-code, business-friendly authoring environment for building and modifying applications visually (cases, data, UI, simple logic) — a simplified view of the same application Dev Studio edits. |
| **Case management** | Pega's core — modeling work as cases (units of work with a lifecycle, e.g. a loan application), structured as stages and steps, with dynamic, adaptive behavior versus rigid hard-coded workflow. |
| **Case type** | A reusable template for a kind of work, defining its lifecycle (stages and steps), data, and rules — the primary artifact a System Architect builds. |
| **CLSA (Certified Lead System Architect)** | Pega's elite System Architect credential (requires CSSA) — earned through a two-part process: a written Architecture Exam plus a hands-on Application Exam that designs and builds a real application. |
| **Customer Decision Hub (CDH)** | Pega's real-time decisioning engine — for every customer interaction, it decides the single Next-Best-Action across all channels; the crown jewel of Pega's customer-engagement side. |
| **DCO (Directly Capture Objectives)** | Pega's methodology where business and IT collaborate in Pega itself to capture requirements directly as executable application artifacts (case stages, steps, rules), eliminating the doc-to-code translation gap. |
| **Dev Studio** | Pega's full developer authoring environment with complete control over every rule and technical detail — where system architects do advanced configuration on the same app App Studio simplifies. |
| **Guardrails** | Pega's best-practice enforcement — continuously scoring an application's guardrail compliance, rewarding model-driven design and flagging risky custom code, to keep apps easy to change and upgrade ("build for change"). |
| **Model-driven** | Pega's development approach — you model an application visually and Pega generates the running app from the model, so the model is the application (no separate codebase to keep in sync). |
| **Next-Best-Action (NBA)** | Pega's decisioning paradigm — for each customer at each moment, determine the single best action (offer, message, retention, service) by arbitrating customer relevance/propensity against business value, gated by eligibility and suitability. |
| **Rule** | The universal building block in Pega — flows, UI, data, decisions, and validation are all rules stored in the rule engine, enabling reuse, versioning, governance, and model-driven change. |
| **Situational layer cake** | Pega's layered architecture for reuse — rulesets organized general-to-specific, so common logic is built once and specialized by layer (business unit, region, channel) and assembled per situation at runtime, avoiding forked copies. |
| **System Architect (CSA / CSSA)** | The Pega developer role and its certifications — Certified System Architect (foundational app-building) and Certified Senior System Architect (designing reusability across business lines). |
| **Pega Robotics** | Pega's RPA capability (Certified Robotics System Architect) — software bots automating repetitive, UI-driven, no-API tasks via Robot Studio, in attended (assisting a human) or unattended (autonomous) modes. |
| **Pega GenAI** | Pega's generative-AI capabilities across the platform, including GenAI Blueprint, which drafts an application design from a natural-language description of a business process. |
| **Guardrail compliance score** | A percentage score Pega assigns to an application reflecting how well it follows best practices — high means model-driven and upgradeable, low means custom-code-heavy and brittle. |
