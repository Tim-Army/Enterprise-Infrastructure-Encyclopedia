# Volume XLI Glossary

Definitions for terms used in **Volume XLI — CNCF and Kubernetes Certification
Tracks**, alphabetized. See also the [volume index](INDEX.md) and the
[master glossary](../../GLOSSARY.md) for cross-volume terminology.

**4Cs of Cloud Native Security** — The nested layers Cloud, Cluster, Container,
and Code, each needing its own controls; the framing model for KCSA. Used in
Chapter 05.

**CAPA (Certified Argo Project Associate)** — The CNCF associate for the Argo
ecosystem: Workflows, CD, Rollouts, and Events. Used in Chapter 08.

**CBA (Certified Backstage Associate)** — The CNCF associate for Backstage,
the internal developer portal framework. Used in Chapter 08.

**CGOA (Certified GitOps Associate)** — The CNCF associate for vendor-neutral
GitOps: terminology, the four principles, patterns, and tooling. Used in Chapter
08.

**CKA (Certified Kubernetes Administrator)** — The CNCF's flagship
performance-based operations credential; five domains led by troubleshooting.
Used in Chapter 03.

**CKAD (Certified Kubernetes Application Developer)** — The CNCF's
performance-based developer credential; five domains. Used in Chapter 04.

**CKS (Certified Kubernetes Security Specialist)** — The CNCF's
performance-based security credential; requires an active CKA. Used in Chapter
05.

**CCA (Cilium Certified Associate)** — The CNCF associate for Cilium's
eBPF-based networking, security, and observability; eight domains. Used in
Chapter 07.

**CNPA (Cloud Native Platform Engineering Associate)** — The multiple-choice
associate for platform engineering and internal developer platforms. Used in
Chapter 09.

**CNPE (Certified Cloud Native Platform Engineer)** — The performance-based
expert credential for building internal developer platforms (launched November
2025). Used in Chapter 09.

**eBPF** — A Linux kernel technology that safely runs sandboxed programs on
events (packets, syscalls); the basis of Cilium's datapath. Used in Chapter 07.

**GitOps** — A delivery model where declarative desired state lives in Git and a
controller continuously reconciles the cluster to it. Used in Chapter 08.

**Golden path** — A paved, opinionated, secure-by-default way to build and ship a
service on an internal developer platform. Used in Chapter 09.

**Hubble** — Cilium's flow-level network observability tool, showing per-flow
identities and policy verdicts. Used in Chapter 07.

**ICA (Istio Certified Associate)** — The CNCF's performance-based service-mesh
credential; four domains led by traffic management. Used in Chapter 07.

**IDP (Internal Developer Platform)** — A self-service platform, often with a
portal like Backstage, that gives developers paved paths on top of Kubernetes.
Used in Chapter 09.

**KCA (Kyverno Certified Associate)** — The CNCF associate for Kyverno,
the Kubernetes-native policy engine (validate, mutate, generate). Used in Chapter
08.

**KCNA (Kubernetes and Cloud Native Associate)** — The CNCF's multiple-choice
entry credential; four domains led by Kubernetes Fundamentals. Used in Chapter
02.

**KCSA (Kubernetes and Cloud Native Security Associate)** — The CNCF's
multiple-choice security-knowledge credential; six domains. Used in Chapter 05.

**killer.sh** — The exam simulator bundled with the Kubernetes core exams for
timed, hands-on practice. Used in Chapter 01.

**OTCA (OpenTelemetry Certified Associate)** — The CNCF associate for
OpenTelemetry telemetry (traces, metrics, logs); four domains led by the API and
SDK. Used in Chapter 06.

**PCA (Prometheus Certified Associate)** — The CNCF associate for Prometheus
metrics and monitoring; five domains led by PromQL. Used in Chapter 06.

**Performance-based exam** — An exam solved by completing real tasks in a live
terminal rather than answering multiple-choice questions; the format of CKA,
CKAD, CKS, ICA, and CNPE. Used in Chapter 01.

**Pod Security Standards** — Kubernetes' built-in admission profiles (privileged,
baseline, restricted) enforced via namespace labels. Used in Chapters 05 and 09.

**PromQL** — The Prometheus query language; `rate()` over a range vector and
aggregation are its core patterns. Used in Chapter 06.

**PSI** — The vendor that delivers the Linux Foundation's remote-proctored exams.
Used in Chapter 01.

**Version pinning** — The practice of tying a curriculum to a specific Kubernetes
version (currently v1.35) so exams track the project. Used in Chapters 01 and 09.
