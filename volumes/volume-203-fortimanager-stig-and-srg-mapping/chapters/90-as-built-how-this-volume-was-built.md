## Theory and Architecture

This is the volume's **as-built chapter**. Like an as-built drawing, it
records how the volume was actually made rather than how it was planned: which
parts were generated by a repeatable workflow, which sources each part rests
on, and which changes came later. It is numbered 90 so that it stays last if
chapters are added, and so that as-built chapters have the same number in every
volume that has one.

The content chapter was not written here. It was built inside
[Volume CLXXII — DISA SRGs and STIGs](../../volume-172-disa-srgs-and-stigs/README.md)
as Chapter 13, by the `/srg-mapping-for` workflow that
[Volume CLXXII's own as-built chapter](../../volume-172-disa-srgs-and-stigs/chapters/90-as-built-how-this-volume-was-built.md)
describes step by step. On 2026-11-20 it moved here, together with its CSV
files, because volume numbers 200 to 299 are reserved for Fortinet STIG work
(see [Structure.md](../../../Structure.md)). This chapter records only what is
specific to the FortiManager material. For the workflow itself (inventory,
agents, playbooks, registration), read the Volume CLXXII chapter.

## Design Considerations

- **The version source is the New Features Guides.** Fortinet publishes no
  feature matrix for FortiManager. Each release train has a New Features
  Guide that tags every feature with the patch release that introduced it,
  and the five guides cover FortiManager 7.0.0 through 8.0.1. The 52 core
  platform features existed before 7.0.0 and are in no guide.
- **The 7.6 titles come from the online guide only.** The feature titles come
  from each guide's table of contents on docs.fortinet.com. For 7.0, 7.2,
  7.4, and 8.0 they were checked against the PDF bookmarks. The 7.6 PDF could
  not be downloaded, so its online table of contents is the only source for
  that train.
- **One SRG applies.** FortiManager has no STIG, and Chapter 01 maps its
  features to the Network Device Management SRG V5R5. If the optional
  FortiAnalyzer features are enabled on a FortiManager, that part is assessed
  against the Central Log Server SRG, as Volume CCII Chapter 01 describes.
- **The weight is on access control, auditing, and change control.** A
  FortiManager administrator can change every managed device, so the map ties
  most template, script, policy, and installation features to those
  requirements.
- **Commands are machine-checked.** Every `config` path, `set` option, option
  value, and `execute` command was tested against the FortiManager 8.0.1 CLI
  Reference, each option against the syntax of the path it is entered under.
  For a feature that is used in the GUI, the command column gives the
  administrator profile permission that limits who can use it. A dash means
  there is nothing to configure, not that a requirement is met.
- **Requirements that FortiManager does not meet exactly are written down.**
  Chapter 01 names them: the number of changed characters in a new password,
  the check against compromised passwords, the limit on local accounts,
  certificate revocation, full-text recording of privileged commands, and NTP
  and SNMP cryptography on older releases. It also records that FIPS-CC mode
  can be enabled only from the console.
- **Prerequisites share wording with FortiAnalyzer.** Where a FortiManager
  prerequisite is the same thing as a FortiAnalyzer one, it uses the same
  wording, although the IDs differ.

## Implementation and Automation

### How the chapter was built

The agent's method was written down afterward as `PLAYBOOK.txt`. For this
chapter the work came to these parts:

1. Collect the version source and the command source: the five New Features
   Guides (the 7.6 guide from its online table of contents) and the
   FortiManager 8.0.1 CLI Reference.
2. List the features: the 52 core platform features, then every topic in the
   five guides under the guide's own category names, 435 in all.
3. Map each feature to a requirement of the NDM SRG, as one of three
   relationships: implements a requirement, must be configured to meet a
   requirement, or no direct requirement. A feature with no direct
   requirement falls under the requirement to prohibit unnecessary functions
   when it is unused.
4. Give the command, the administrator profile permission, or the GUI pane,
   and check every command against the CLI Reference text.
5. Write the requirement reference, which lists the 79 requirements the map
   uses.

The prerequisites pass of 2026-10-16 added the *FortiManager prerequisites*
table (P1 to P23) and a prerequisites column on all 487 feature rows. No row
or command changed.

### The CSV files

One script writes the downloads:

```bash
python scripts/python/export_srg_tables.py
```

It finds each table in Chapter 01 by its heading, writes it to
`data/<chapter>-<suffix>.csv`, and inserts or refreshes the download link on
the line before the table. The CSV files use UTF-8 with a byte-order mark, so
spreadsheet programs show dashes and quotes correctly.
`scripts/bash/build-download-site.sh` copies them to the portal at
`data/volume-203-fortimanager-stig-and-srg-mapping/`.

### The move from Volume CLXXII

The `/stig-volume-for` workflow made the move on 2026-11-20. Its script is
`.claude/skills/stig-volume-for/move_product.py`, and
[Volume CLXXII's Chapter 90](../../volume-172-disa-srgs-and-stigs/chapters/90-as-built-how-this-volume-was-built.md)
describes it. The move changed these things:

- Chapter 13 of Volume CLXXII became Chapter 01 here, with its `data/`
  files renamed to match.
- Cross-references inside the chapter were rewritten. A reference to a moved
  chapter uses its new number. A reference to a chapter that stays in Volume
  CLXXII names the volume and links across by relative path. A reference to a
  chapter that moved to another volume earlier names that volume.
- `scripts/python/export_srg_tables.py` covers this volume.
- Volume CLXXII's README and index point to the new location, and its
  Chapter 90 records the move.
- The portal URLs of the moved CSV files changed from
  `data/volume-172-disa-srgs-and-stigs/` to
  `data/volume-203-fortimanager-stig-and-srg-mapping/`, with new file names.

The move left one thing where it was. The scratch folders that built the
chapter (`temp/fmg/` and `temp/pq-fmg/`)
are not tracked, and their scripts still name the Volume CLXXII paths. Change
those paths before you run one of them again, or it reads a pointer page or
writes over one.

## Validation and Troubleshooting

To check this volume:

- **Row counts.** Chapter 01 has 23 rows in *FortiManager prerequisites*, 487 rows in *The FortiManager feature map*, and 79 rows in *Requirement reference*. The CSV files must match: run
  `python scripts/python/export_srg_tables.py` and confirm a clean `git status`
  afterward.
- **The move.** `python .claude/skills/stig-volume-for/move_product.py "FortiManager" --check`
  looks for chapter references that were not rewritten, links of this volume
  that do not resolve, and an export that changes a file.
- **Repository checks.** `scripts/bash/validate.sh` checks `book.yml`, internal
  links, markdownlint, and cspell.

Common problems:

| Symptom | Cause | Fix |
| --- | --- | --- |
| A link to a CSV file returns 404 on the portal | The link uses the Volume CLXXII path or an old file name | Run `export_srg_tables.py` to refresh the link |
| A reader lands on a short page at Chapter 13 of Volume CLXXII | They followed an old link | The page links to the new chapter; nothing to fix |
| A scratch script writes a full chapter into Volume CLXXII | The script still names the old path | Restore the pointer page with `git checkout`, then change the path in the script |

## Security and Best Practices

- **Treat the map as a starting point, not a ruling.** Confirm each mapping
  with your assessor, especially where a requirement is organization-defined.
- **Confirm SRG and STIG releases with DISA.** Download the current files from
  DoD Cyber Exchange before citing an ID in an authorization package.
- **Confirm prerequisites for your exact model and release.** Licenses and
  hardware support differ by model and release.
- **Do not commit the downloaded documents.** The scratch folders under
  `temp/` hold vendor documents and are not tracked.
- **Keep this chapter current.** When a chapter, a table, or the export script
  changes, update this chapter in the same commit.
