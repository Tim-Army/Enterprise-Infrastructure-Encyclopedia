# Volume LXIV Glossary

Definitions for terms introduced in **Volume LXIV — HPE Aruba Networking Certification Tracks**.
See the [master glossary](../../GLOSSARY.md) for cross-volume terms.

- **ACA / ACP / ACX** — the HPE Aruba Networking Certified Associate, Professional, and Expert tiers.
- **AOS-CX** — Aruba's modern switch operating system, built around a state database with a built-in REST API, making it programmable by design.
- **AOS-10** — the operating system for Aruba access points and gateways in the Central-managed architecture.
- **AirMatch** — Aruba's centralized RF optimization that tunes channel and power across the WLAN.
- **Advanced Product Certification (APC)** — product-specific HPE Aruba credentials (e.g., ClearPass, Central, Comware, CX 10000, AOS-10).
- **Aruba Central** — the cloud-native management, monitoring, AIOps, and orchestration plane for Aruba switches, APs, and gateways.
- **ClearPass** — Aruba's network access control (NAC) and policy platform: authentication (802.1X/MAC/portal over RADIUS), profiling, posture, and role assignment.
- **CX 10000** — a "distributed services switch" with an embedded Pensando DPU that runs a stateful firewall and services in the switch data path for line-rate east-west segmentation.
- **Dynamic segmentation** — enforcing a user/device role consistently across wired and wireless, regardless of where they connect.
- **EVPN-VXLAN** — a VXLAN overlay whose MAC/IP reachability is distributed by the BGP EVPN control plane, used to build scalable leaf-spine fabrics.
- **HPE6- / HPE7-** — the exam-code prefixes for Associate (HPE6-Axx) and Professional/Expert/Architect (HPE7-Axx) HPE Aruba Networking exams.
- **NetConductor** — Aruba Central's fabric orchestration that builds EVPN-VXLAN overlays and roles from intent.
- **Network Architect** — the HPE Aruba design credential tier (Campus Access HPE7-A03, Data Center HPE7-A04).
- **Policy Enforcement Firewall (PEF)** — the per-role stateful firewall on Aruba gateways and AOS-CX that enforces dynamic segmentation.
- **pyaoscx** — Aruba's official Python SDK for the AOS-CX REST API.
- **VSF (Virtual Switching Framework)** — stacking multiple AOS-CX access switches into one logical, single-managed unit.
- **VSX (Virtual Switching Extension)** — pairing two AOS-CX aggregation switches into one logical, active-active unit with independent control planes.
- **arubanetworks.aos_cx** — the certified Ansible collection for declarative AOS-CX configuration.
